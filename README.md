# GPS_week_rollover
ПП. Преодоление проблемы временного сдвига при переполнении целочисленного счетчика недель.

## Задачи
- [x] Считывание входного сигнала на одном последовательном порте
- [x] Корректировка считанных строк
- [x] Отправка данных на другой последовательный порт

## Оборудование
1. DOIT ESP32 Devkit V1
   - Тактовая частота: до 240 МГц
   - Flash-память: 448 КБ
   - Внешняя Flash-память: 4 МБ
   - SRAM-память: 520 КБ
   - Аппаратные интерфейсы: 3×SPI, 3×UART, 2×I²C и 2×I²S
   - Напряжение логических уровней: 3,3 В
   - Максимальный ток с пина или на пин: 12 мА
   - Максимальный выходной ток пина 3V3: 1 А

2. GPS модуль LOCOSYS LS23060 v1.0
   
## Особенности
При обработке строки с датой возникает задержка в ~270 мкс<br>
В GPS модуле была выпаяна батарейка, обеспечивающая SRAM память. Поэтому конфигурация становится заводской при каждом выключении (в т.ч. скорость передачи данных, для нее в коде v2 сделан костыль)<br>
Способен работать до ~2106 года (по заявлению автора библиотеки Stamp)<br>
Число сдвигов определяется вручную (за него отвечает параметр NUM_OF_ROLLS)<br>
В GPS модуле уже была зашита прошивка, учитывающая сдвиг в 1999 году. Поэтому в коде число сдвигов равно 1 (всего уже было 2). <br>

Даты сдвигов:
   - 5-6 января 1980 года (начало работы системы навигации)
   - 21-22 августа 1999 года (произошел первый сдвиг)
   - 6-7 апреля 2019 года (произошел второй сдвиг)
   - 20-21 ноября 2038 года (произойдет третий сдвиг, NUM_OF_ROLLS поменять с 1 на 2)<br>
